- X.200 5.2.2.4 (p. 12): the layers "communicate by means of the set of services provided by the (N–1)-layer", and the lowest layer communicates "directly via the physical media".
- X.200 6.1.6 (p. 33): relay open systems pass data on when "the physical media for OSI do not link all open systems directly".
- NIST SP 800-77r1 2.1 (p. 20): "the data is passed from the highest layer through intermediate layers to the lowest layer", and later "the data is then passed up through the layers to its destination".
- Cisco: "removes the outer IP header of an encapsulated packet".
- RFC 2003 §1: "it is decapsulated, yielding the original IP datagram".
- Defining standard: X.200 for the layering and relaying. NIST, Cisco and RFC 2003 confirm independently.
- Currency: all sources current.

### units[0].learn.why[0] ("why-1"): ✅

"Why split the job? Each layer can use the service of the layer below without knowing the details of how that service is done."

- Microsoft Learn, Introduction: "Each layer offers specific services to higher layers while shielding these layers from the details".
- X.200 5.2.2.3 (p. 11): "each (N)-layer provides (N+1)-entities ... with an (N)-service".
- X.200 6.2.1 (p. 33), principle j): "changes of functions or protocols to be made within a layer without affecting other layers".
- X.200 7.4.2.1 (p. 41): the transport-service "relieves them from any concern with the detailed way".
- X.200 7.5.2.3 (p. 45): "It makes invisible to transport-entities how underlying resources ... are used".
- These are two independent sources: X.200 and Microsoft. X.200 is also a defining standard for its layering principles.
- Currency: X.200 in force. The Microsoft page is live.

### units[0].learn.why[1] ("why-2"): ✅

- Currency: X.200 in force.

### units[0].learn.deep[1] ("deep-2", Learn's Go deeper): ✅

"The internet’s own protocols use four layers: Application, Transport, Internet and Link. NIST calls the lower two Network and Data Link."

- RFC 1122 1.1.3: "The protocol layers used in the Internet architecture are as follows", followed by Application Layer, Transport Layer, Internet Layer and Link Layer.
- NIST SP 800-77r1 2.1 (p. 20): "IP communications are roughly composed of four layers that work together." Its Figure 1 names Application, Transport, Network and Data Link.
- Defining standard: RFC 1122 (STD 3) defines the protocol layers of the Internet architecture that hosts implement. NIST confirms the four layers and its own names for them.

### units[0].learn.deep[2] ("deep-3", Learn's Go deeper): ✅

"A **segment** is a TCP header followed by application data. An IP **datagram** is an IP header followed by transport data; it travels as one **packet**, or as several when fragmented. A **frame** is a link-layer header followed by a packet."

- RFC 1122 1.3.3:
  - "A segment consists of a TCP header followed by application data."
  - "An IP datagram consists of an IP header followed by transport layer data".
  - "A packet may be a complete IP datagram or a fragment of an IP datagram."
  - A frame "consists of a link-layer header followed by a packet."
- NIST SP 800-77r1 2.1, footnote 6 (p. 20): "the logical units are typically composed of a header and a payload".
- Defining standard: RFC 1122 (STD 3) 1.3.3 defines the Internet architecture's data-unit terms segment, message, IP datagram, packet and frame. RFC 9293, which now holds the TCP requirements, defines a segment consistently: "the unit of data transferred between a pair of TCP modules".
- Currency: RFC 1122 is not obsoleted, and no update touches 1.3.3.
