### units[0].steps[0].deep[0] (step "application", Go deeper) — ✅

"In X.200, the Application Layer is an application’s only way into the OSI environment. As the highest layer, it has no boundary with a layer above it."

- X.200 7.1.2.1 (p. 36), defining standard: X.200 defines the OSI layers, including the Application Layer. "As the highest layer in the Reference Model of Open Systems Interconnection, the Application Layer provides the sole means for the application process to access the OSIE. Hence the Application Layer has no boundary with a higher layer."
- Currency: X.200 (07/94) in force.

### units[0].steps[1].deep[0] (step "presentation", Go deeper) — ✅

"In X.200, the way data is written while it travels between two systems is its **transfer syntax**. Layer 6 selects transfer syntaxes that both ends accept, and keeps the meaning of the application’s data intact on the way."

- X.200 6.1.2 (p. 32), defining standard (layer numbering): "b) the Presentation Layer (layer 6);"
- X.200 7.2.1.2 (p. 37), defining standard (defines transfer syntax): "transfer syntax: The abstract and concrete syntax used in the transfer of data between open systems."
- X.200 7.2.2.3 (p. 37), defining standard (defines the Presentation Layer's purpose): "The Presentation Layer ensures that the information content of the Application Layer data is preserved during transfer." … "the Presentation Layer is responsible for selecting mutually acceptable transfer syntaxes."
- Currency: X.200 (07/94) in force.

### units[0].steps[1].deep[1] (step "presentation", Go deeper) — ✅

"The internet’s own protocols have no separate presentation layer: their application layer essentially combines the functions of OSI’s Presentation and Application layers."

- RFC 1122 1.1.3 (p. 8–9), defining standard: RFC 1122 (Internet Standard, STD 3) defines the layers of the Internet protocol suite that hosts implement. "The Internet suite does not further subdivide the application layer" … "The application layer of the Internet suite essentially combines the functions of the top two layers -- Presentation and Application -- of the OSI reference model."
- Currency: RFC 1122 is not obsoleted. Its updates (RFC 1349, 4379, 5884, 6093, 6298, 6633, 6864, 8029, 9293) change TOS, 127/8 handling, TCP urgent/RTO, Source Quench, the IPv4 ID field and TCP requirements; none changes the §1.1.3 layer description. The Internet suite still has no separate presentation layer.

### units[0].steps[3].deep[1] (step "transport", Go deeper) — ✅

"On the internet, the two main transport protocols are **TCP**, which is reliable and also puts data back in order and controls its flow, and **UDP**, a connectionless “datagram” service."

- RFC 1122 1.1.3 (p. 9), defining standard: RFC 1122 (STD 3) defines the Internet suite's transport layer for hosts and names its protocols. "There are two primary transport layer protocols at present:" … "TCP is a reliable connection-oriented transport service that provides end-to-end reliability, resequencing, and flow control. UDP is a connectionless ("datagram") transport service."
- NIST SP 800-77r1 2.1 (p. 20): "TCP, which provides reliable connection-oriented communications, and the User Datagram Protocol (UDP), which provides unreliable connectionless communications, are commonly used transport layer protocols."
- Currency: RFC 1122 not obsoleted. RFC 9293 (2022) updates RFC 1122's TCP requirements; read for this check, it still says "TCP provides a reliable, in-order, byte-stream service to applications." NIST SP 800-77r1 (2020) confirms TCP and UDP remain the common transport protocols.

### units[0].steps[4].deep[1] (step "network", Go deeper) — ✅

"On the internet, the main network layer protocol is **IP**, the Internet Protocol. IP itself guarantees no delivery: data may arrive out of order or not at all, and the layers above make delivery reliable when that is needed."

- RFC 1122 1.1.3 (p. 10), defining standard: RFC 1122 (STD 3) defines the Internet layer of the suite. "All Internet transport protocols use the Internet Protocol (IP) to carry data from source host to destination host. IP is a connectionless or datagram internetwork service, providing no end-to-end delivery guarantees. Thus, IP datagrams may arrive at the destination host damaged, duplicated, out of order, or not at all. The layers above IP are responsible for reliable delivery service when it is required."
- NIST SP 800-77r1 2.1 (p. 20): "Network Layer. This layer routes packets across networks. IP is the fundamental network layer protocol for TCP/IP."
- Currency: RFC 1122 not obsoleted; RFC 6864's update concerns only the IPv4 ID field. IP's best-effort service is still current practice.

### units[0].steps[5].deep[0] (step "data-link", Go deeper) — ⚠️

- X.200 7.6.2.2 (p. 50), defining standard: "The Data Link Layer detects and possibly corrects errors which may occur in the Physical Layer."
- X.200 7.6.4.5 (p. 52), defining standard (defines the delimiting and synchronization functions): "These functions provide recognition of a sequence of physical-service-data-units (i.e. bits, see 7.7.3.2) transmitted over the physical-connection, as a data-link-protocol-data-unit. NOTE – These functions are sometimes referred to as framing."
- The condition, from X.200 7.6.4 (p. 51): "In connection-mode, the following functions are also performed by the Data Link Layer:" … "e) delimiting and synchronization;". The functions performed in both modes do not include delimiting and synchronization.
- Currency: X.200 (07/94) in force.
