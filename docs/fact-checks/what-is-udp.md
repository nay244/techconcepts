### units[0].steps[0].deep[0] (step "connectionless-send", Go deeper) — ✅

The UDP header is four 2-byte fields; no sequence number, ACK or window; an app can add RTP inside with a sequence number and timestamp, to order packets and play them on time.

- `rfc-768` §Fields
  > Length  is the length  in octets  of this user datagram  including  this
  > header  and the data.   (This  means  the minimum value of the length is
  > eight.)
- Note: RFC 768 defines the UDP header format; its format figure shows exactly four 16-bit fields (source port, destination port, length, checksum) and nothing else, so there is no sequence, acknowledgment or window field. RFC 768 is updated by RFC 9868, which adds options after the user data, not in the header; it is not obsoleted.
- `rfc-3550` §5.1
  > The sequence number increments by one for each RTP data packet
  > sent, and may be used by the receiver to detect packet loss and to
  > restore packet sequence.
- Note: RFC 3550 defines the RTP header and its sequence number and timestamp fields.
- `rfc-3550` §2.1
  > To
  > cope with these impairments, the RTP header contains timing
  > information and a sequence number that allow the receivers to
  > reconstruct the timing produced by the source
- `rfc-3551` §4.1
  > the RTP
  > header carries both a sequence number and a timestamp
- Note: RFC 3550 and RFC 3551 are Standards Track and not obsoleted.

### units[0].steps[1].deep[0] (step "datagram-stream", Go deeper) — ✅

Fifty packets a second at 20 ms each; real-time apps care about latency and jitter; the receiver's jitter buffer discards a packet that arrives too late.

- `itu-g114` §Annex A.3
  > Packetized transmission systems exhibit variable delay (jitter) in packet delivery time.
- `itu-g114` §Annex A.3
  > If the delivery time of a packet exceeds the length of the
  > receive buffer, then this packet "arrives too late" with respect to its intended play-out time, and will
  > be discarded.
- `rfc-3611` §4.7
  > The block reports separately on packets lost on the IP channel, and
  > those that have been received but then discarded by the receiving
  > jitter buffer.
- `rfc-3550` §6.4.1
  > An estimate of the statistical variance of the RTP data packet
  > interarrival time
- Note: RFC 3550 defines the RTP interarrival jitter measure. Fifty a second is 1000 ms divided by 20 ms. G.114 (05/2003) is listed by ITU-T as in force; RFC 3611 is not obsoleted.

### units[0].steps[2].deep[0] (step "packet-loss-no-retransmission", Go deeper) — ✅

UDP has no retransmission; a call app sees loss as a sequence gap and in RTCP reports; UDP has no congestion control, so an app without a congestion-controlled transport has to control its own rate.

  > these are required.
- `rfc-8085` §1

  > up to the applications that use UDP for Internet communication to
  > employ suitable mechanisms to prevent congestion collapse and
  > establish a degree of fairness.
- `rfc-8085` §3.1
  > If an application or protocol chooses not to use a congestion-controlled transport protocol, it SHOULD control the rate at which it
