# Fact-check: glossary group `subnets`

Every source was fetched from its publisher on 2026-11-13: RFCs as plain text from rfc-editor.org, the Microsoft Learn and Cisco pages as HTML, ITU-T X.200 and NIST FIPS 197 as PDFs (text saved with `pdftotext -raw`). Every item passes. Notes under each claim say where a sentence is looser than its source.

## The claims

### entry "bit": statement "bit-1" — ✅

"A bit, short for binary digit, is a single digit that is either 0 or 1."

- `rfc-4949` §4
  > A contraction of the term "binary digit"; the smallest unit of
  > information storage, which has two possible states or values. The
  > values usually are represented by the symbols "0" (zero) and "1"
  > (one).
- `nist-fips-197` §2.1
  > Bit A binary digit: 0 or 1.
- Note: two independent sources (an IETF RFC and a NIST standard) each give both the full name and the two values.
- Note: currency. RFC 4949 is Informational and not obsoleted. FIPS 197 (updated 9 May 2023) is final on NIST CSRC, not withdrawn or superseded.

### entry "bit": statement "bit-2" — ✅

"An IPv4 address is 32 bits long, usually written as four numbers of 8 bits each, from 0 to 255."

- `rfc-791` §2.3
  > Addresses are fixed length of four octets (32 bits).
- Note: RFC 791 (STD 5) defines the IPv4 address format, so it fixes the 32-bit length and the four octets. It does not describe the written form.
- `microsoft-tcpip-subnetting` §IP addresses, networks and hosts
  > IP addresses are normally expressed in dotted-decimal format, with four numbers separated by periods, such as 192.168.123.132.
- `microsoft-tcpip-subnetting` §Glossary
  > Octet--An 8-bit number, 4 of which comprise a 32-bit IP address. They have a range of 00000000-11111111 that correspond to the decimal values 0-255.
- `rfc-4632` §3.1
  > In CIDR notation, a prefix is shown as a 4-octet
  > quantity, just like a traditional IPv4 address or network number
- `cisco-ip-subnets` §Understand IP Addresses
  > The 32 binary bits are broken into four octets (1 octet = 8 bits). Each octet is converted to decimal and separated by a period (dot). …
  > The value in each octet ranges from 0 to 255 decimal, or 00000000 - 11111111 binary.
- Note: the written form (four numbers, 8 bits each, 0 to 255) is confirmed by two different vendors, Microsoft and Cisco.
- Note: currency. RFC 791 is an Internet Standard and not obsoleted. Its updates (RFC 1349, 2474, 6864) cover the type-of-service and identification fields, not the address format.

### entry "bit": statement "bit-3" — ✅

"The Physical Layer, layer 1 of the OSI model, sends data as bits over a physical medium."

- `itu-x200` §7.7.2
  > The Physical Layer provides the mechanical, electrical, functional and procedural means to activate, maintain, and
  > de-activate physical-connections for bit transmission between data-link-entities. …
  > Physical Layer entities are
  > interconnected by means of a physical medium.
- `itu-x200` §6.1.2
  > g) the Physical Layer (layer 1).
- Note: X.200 (07/1994) is the defining standard for the OSI layers. It defines the Physical Layer's purpose (§7.7.2) and its number (§6.1.2).
- `microsoft-osi` §Physical layer
  > This layer manages the reception and transmission of the unstructured raw bit stream over a physical medium.
- Note: currency. ITU-T lists X.200 (07/1994) as in force. The Microsoft Learn page is live (last updated 2025-01-31).

### entry "borrowing-bits": statement "borrowing-bits-1" — ✅

"Borrowing bits is making subnets by turning some of the host portion’s bits into network bits, with a longer subnet mask."

- `rfc-950` §1
  > Use a single network number, and partition the host address
  > space by assigning subnet numbers to the LANs ("explicit
  > subnets").
- `rfc-950` §2.1
  > Masked bits: Use a bit mask ("address mask") to identify
  > which bits of the local address field indicate the subnet
  > number.
- Note: RFC 950 (STD 5) is the defining standard for IPv4 subnetting: it takes the subnet number from bits of the host (local address) part and marks them with a mask. It does not use the word "borrowing". The two vendor pages below do.
- `microsoft-tcpip-subnetting` §Subnetting
  > you divide your network into four subnets by using a subnet mask that makes the network address larger and the possible range of host addresses smaller. In other words, you are 'borrowing' some of the bits used for the host address, and using them for the network portion of the address.
- `cisco-host-subnet-quantities` §Subnetting and Tables
  > As a concept, subnetting divides the network into smaller portions called subnets. This is done with borrowed bits from the host portion of the IP address
- Note: currency. RFC 950 is an Internet Standard and not obsoleted. Its one update, RFC 6918, retires the ICMP address mask messages, which this claim does not touch.

### entry "borrowing-bits": statement "borrowing-bits-2" — ✅

"Each bit borrowed doubles the number of subnets and halves their size: 2 bits of a /24 make four subnets of 64 addresses."

- `rfc-4632` §3.1
  > prefixes may be defined to describe any power of two-sized block of
  > between one and 2^32 end system addresses.
- `rfc-4632` §3.1
  > n.n.n.x/26 64 67108864
- Note: RFC 4632 is the current standard (BCP) for classless prefixes. Its table gives the size of each prefix length, and each step down the table halves the block size.
- `microsoft-tcpip-subnetting` §Subnetting
  > The subnet mask 255.255.255.192 gives you four networks of 62 hosts each. …
  > In these four networks, the last six binary digits can be used for host addresses.
- `cisco-host-subnet-quantities` §Subnet Example
  > borrows two bits (the leftmost bits) from the host portion of the network for subnetting …
  > Each of these can represent a subnet.
- Note: Microsoft and Cisco each confirm four subnets from two borrowed bits. Microsoft's six host bits give 64 addresses each (62 usable), which matches RFC 4632's /26 block of 64.
- Note: currency. RFC 4632 is a Best Current Practice and not obsoleted. The Microsoft page was last updated 2026-02-12, and the Cisco page 2023-05-17. Both are live.

### entry "broadcast-address": statement "broadcast-address-1" — ✅

"A broadcast address is the last address of a network or subnet: its host portion is all 1s."

- `rfc-1122` §3.2.1.3
  > and the notation "-1" for a field that contains all 1 bits. …
  > Directed broadcast to the specified network.
- `rfc-919` §7
  > The number whose bits are all ones has
  > this property
- Note: RFC 919 (STD 5) is the defining standard for IP broadcast addressing, and RFC 1122 (STD 3) restates the special addresses. Both are current.
- `microsoft-tcpip-subnetting` §Glossary
  > Broadcast address--An IP address with a host portion that is all ones.
- `microsoft-tcpip-subnetting` §Subnetting
  > The 255 address (in binary notation, a host address of all ones) is used to broadcast a message to every host on a network. Just remember that the first and last address in any network or subnet can't be assigned to any individual host.
- Note: the sentence leaves out the limited broadcast address 255.255.255.255, which statement 3 of the same entry covers. It also leaves out the /31 subnet, which has no broadcast address (point-to-point-link-3).
- Note: currency. RFC 919 is an Internet Standard with no updates and is not obsoleted. RFC 1122 is not obsoleted, and its updates (RFC 1349, 4379, 5884, 6093, 6298, 6633, 6864, 8029, 9293) do not touch addressing.

### entry "broadcast-address": statement "broadcast-address-2" — ✅

"A packet sent to it goes to every device on that network."

- `rfc-919` §7
  > broadcast to all of net 36 by using 36.255.255.255
- `rfc-919` §7
  > 36.255.255.255
  > means "all hosts on network number 36".
- `rfc-1122` §3.2.1.3
  > Directed broadcast to the specified network.
- `microsoft-tcpip-subnetting` §Subnetting
  > The 255 address (in binary notation, a host address of all ones) is used to broadcast a message to every host on a network.
- Note: RFC 919 is the defining standard, and Microsoft confirms it independently.
- Note: this describes the ordinary case of sending from inside the network. RFC 2644, an update to the router requirements, makes routers drop directed broadcasts that come from other networks by default. A beginner reading this sentence would not be misled about the local case.
- Note: currency, as for broadcast-address-1.

### entry "broadcast-address": statement "broadcast-address-3" — ✅

"It is normally not given to any device; 255.255.255.255 is a separate broadcast address that reaches only the local network."

- `rfc-1122` §3.2.1.3
