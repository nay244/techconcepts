### entry "application-layer": statement "application-layer-1" — ✅

The Application Layer is layer 7, the top layer of the OSI model.

- `itu-x200` §6.1.2
  > The Reference Model contains seven layers:
  > a) the Application Layer (layer 7);
- `itu-x200` §6.1.4
  > The highest is the Application Layer and it consists of the application-entities that cooperate in the OSI
  > Environment.
- `paloalto-layer-7` §What Is Layer 7?
  > Layer 7 is the application layer and highest level of the Open Systems Interconnection (OSI) model
- Note: X.200 (07/1994) is the defining standard for the OSI layers, their names and numbers. ITU-T lists it as in force.

### entry "application-layer": statement "application-layer-2" — ✅

It is how an application reaches the network: it holds the parts of applications that communicate, and the layers below provide the services they use.

- `itu-x200` §7.1.2.1
  > As the highest layer in the Reference Model of Open Systems Interconnection, the Application Layer provides
  > the sole means for the application process to access the OSIE.
- `itu-x200` §6.1.4
  > it consists of the application-entities that cooperate in the OSI
  > Environment. The lower layers provide the services through which the application-entities cooperate.
- `paloalto-layer-7` §Layer 7 Explained
  > Layer 7 provides the interface between the applications we use and the underlying network over which our data must travel.
- Note: X.200 defines the Application Layer's purpose. Its term is the OSI environment, which the claim calls the network. Palo Alto's explainer uses the same plain wording. The "parts of applications that communicate" are X.200's application-entities.

- Note: X.200 is the defining standard for the OSI layers and their numbers. It is in force.

### entry "data-link-layer": statement "data-link-layer-2" — ✅

  > physical-connections.

  > interface to that network.
- Note: X.200 defines the Data Link Layer's purpose and places it on top of the Physical Layer's connections. Two independent sources, Microsoft's page and RFC 1122, also state the frames and the hop to the next node. "One machine to the next" is the plain form of node-to-node over one link.

### entry "decapsulation": statement "decapsulation-1" — ✅

Decapsulation, or de-encapsulation, is the reverse of encapsulation: taking off an outer header to reach the data inside.

- `rfc-2003` §1
  > Once the
  > encapsulated datagram arrives at this intermediate destination node,
  > it is decapsulated, yielding the original IP datagram
- `rfc-2003` §3
  > To encapsulate an IP datagram using IP in IP encapsulation, an outer
  > IP header [10] is inserted before the datagram's existing IP header
- `rfc-8085` §3.1.11
  > which decapsulates the UDP datagrams and forwards
  > the original packets contained in the payload.
- `paloalto-layer-7` §De-Encapsulation Process (Data Flow Upwards)
  > De-Encapsulation Process (Data Flow Upwards)
- `paloalto-layer-7` §De-Encapsulation Process (Data Flow Upwards)
  > Once data reaches the destination device, it ascends the OSI layers in a reverse process.
- Note: RFC 2003 and RFC 8085 are two different standards that each describe decapsulation as removing the added outer header to recover what was inside. Palo Alto gives the spelling de-encapsulation and calls it the reverse of encapsulation. Some protocols also add a trailer, which the claim leaves out.

### entry "decapsulation": statement "decapsulation-2" — ✅

  > header by the local network interface and handed to the internet
  > module.
- `rfc-1122` §3.1

  > transport-layer protocol module.

- Note: RFC 791, RFC 1122 and NIST SP 800-77r1 are independent, and each states the upward hand-off at the receiver.

### entry "decapsulation": statement "decapsulation-3" — ✅

A router does it to the frames it receives; a tunnel’s far end, to recover the original packet.

- `rfc-1812` §1
  > It generally removes the Link Layer header a
  > message was received with, modifies the IP header, and replaces the
  > Link Layer header for retransmission.
- `rfc-1812` §2.3
  > Encapsulating and decapsulating the IP datagrams with the
  > connected network framing (e.g., an Ethernet header and
  > checksum),
- `rfc-791` §2.2
  > The datagram arrives at a gateway host wrapped in the local network
  > header, the local network interface strips off this header, and
  > turns the datagram over to the internet module.
- `rfc-2003` §1
  > This use of encapsulation and decapsulation of a
  > datagram is frequently referred to as "tunneling" the datagram
- `rfc-8085` §3.1.11
  > a tunnel endpoint encapsulates the packets of
  > another protocol inside UDP datagrams and transmits them to another
  > tunnel endpoint, which decapsulates the UDP datagrams and forwards
  > the original packets contained in the payload.
- Note: RFC 1812 is the defining standard for what an IPv4 router does, including taking off the link-layer framing of what it receives. RFC 791 defines IP's model of operation and shows the gateway doing the same. RFC 2003 and RFC 8085 independently state that a tunnel's exit point decapsulates to recover the original packet.

### entry "encapsulation": statement "encapsulation-1" — ✅

Encapsulation is wrapping data on its way down the layers: a layer carries what the layer above handed it inside a larger unit of its own, adding its own information, usually a header.

- `nist-sp800-77r1` §2.1
  > When a user wants to transfer data across networks, the data is passed from the highest layer
  > through intermediate layers to the lowest layer
- `nist-sp800-77r1` §2.1
  > Essentially, the data produced by a layer is
  > encapsulated in a larger container by the layer below it.
- `nist-sp800-77r1` §2.1, footnote 6
  > At each layer, the logical units are typically composed of a header and a payload. The payload consists of the information
  > passed down from the previous layer, while the header contains layer-specific information such as addresses.
- `rfc-1122` §1.3.3
  > A segment is transmitted by
  > encapsulation inside an IP datagram.
- `paloalto-layer-7` §How Does Data Flow Through the OSI Model?
  > Data flows through the OSI model in a process known as encapsulation and de-encapsulation, which happens when data is sent from a source device to a destination device.
- Note: NIST and RFC 1122 are independent, and both state the wrapping by the layer below. The claim describes the layered case. It leaves out tunnels, where a packet is wrapped inside another of the same kind. This group's decapsulation entry names tunnels, and the claim does not deny them. Its "usually a header" allows for a trailer as well.

### entry "encapsulation": statement "encapsulation-2" — ✅

For example, a TCP segment travels inside an IP datagram, and on each link the IP packet travels inside a frame.

- `rfc-1122` §1.3.3
  > A segment is transmitted by
  > encapsulation inside an IP datagram.
- `rfc-1122` §1.3.3
  > A frame is the unit of transmission in a link layer
  > protocol, and consists of a link-layer header followed by
  > a packet.
- `rfc-9293` §3.1
  > TCP segments are sent as internet datagrams.
- `rfc-791` §2.2
  > The local network interface creates a local network header, and
  > attaches the datagram to it, then sends the result via the local
  > network.
- `rfc-1812` §2.3
  > Encapsulating and decapsulating the IP datagrams with the
  > connected network framing
- Note: RFC 9293 is the current defining standard for TCP, and it states that segments travel as IP datagrams. RFC 791 defines IP and shows a new local network header made for each network crossed, which is the "on each link" part.

### entry "layer": statement "layer-1" — ✅

- `itu-x200` §5.2.1.2
  > (N)-layer: A subdivision of the OSI architecture, constituted by subsystems of the same rank (N).
- `itu-x200` §5.2.2.1
  > According to this technique, each open system is viewed as logically composed of an ordered set of (N)-subsystems,
- `microsoft-osi` §Introduction
  > a series of protocol layers with a specific set of functions allocated to each layer.
- `rfc-1122` §1.1.3
  > a host must implement
  > the layered set of protocols comprising the Internet protocol
  > suite.
- Note: X.200 defines a layer within the OSI architecture. Microsoft and RFC 1122 independently use the same idea.

### entry "layer": statement "layer-2" — ✅

Each layer except the top offers services to the layer above, which uses them without needing the details of how they are done.

- `itu-x200` §5.2.2.3
  > Except for the highest layer, each (N)-layer provides (N+1)-entities in the (N+1)-layer with an (N)-service at
  > (N)-SAP(s).
- `itu-x200` §5.2.2.5
  > The services of an (N)-layer are provided to the (N+1)-layer using the (N)-functions performed within the
  > (N)-layer
- `itu-x200` §7.4.2.1
  > relieves them from any
  > concern with the detailed way in which reliable and cost effective transfer of data is achieved.
- `itu-x200` §7.5.2.3
  > It provides to the transport-entities independence from routing and relay consideration
- `microsoft-osi` §Introduction
  > Each layer offers specific services to higher layers while shielding these layers from the details of how the services are implemented.
- Note: X.200 defines the service relation between adjacent layers. Microsoft states the hidden-details part directly.

### entry "network-layer": statement "network-layer-1" — ✅

The Network Layer is layer 3 of the OSI model.

- `itu-x200` §6.1.2
  > e) the Network Layer (layer 3);
- Note: X.200 is the defining standard for the OSI layers and their numbers.

### entry "network-layer": statement "network-layer-2" — ✅

It carries data between the two end machines, across several networks if need be, finding a route between network addresses.

- `itu-x200` §7.5.3.1.1
  > The basic service of the Network Layer is to provide the transparent transfer of data between transport-entities.
- `itu-x200` §7.5.2.3
  > This includes the case where several subnetworks are used
  > in tandem (see 7.5.4.2) or in parallel.
- `itu-x200` §7.5.4.2.1
  > Routing functions determine an appropriate route between network-addresses.
- `microsoft-osi` §Network layer
  > This layer determines the physical path that the data should take
- `nist-sp800-77r1` §2.1
  > Network Layer. This layer routes packets across networks.
- Note: X.200 defines the Network Layer's service and routing function. The transport-entities are in the end systems, which the claim calls the end machines. Microsoft and NIST independently state the routing.

### entry "network-layer": statement "network-layer-3" — ✅

The layers above need not know how the route is chosen; routers, which relay data between networks, need only layers 1 to 3.

- `itu-x200` §7.5.2.1
  > provides to the transport-entities independence of routing and
  > relay considerations.
- `itu-x200` §6.1.6
  > some open systems act only as relay open systems, passing data to other open
  > systems. The functions and protocols which support the forwarding of data are then provided in the lower layers.
- `itu-x200` §7.5.2.4
  > Any relay functions and hop-by-hop service enhancement protocols used to support the network-service
  > between the OSI end systems are operating below the Transport Layer, i.e. within the Network Layer or below.
- `itu-x200` §5.2.2.3
  > Such open systems need not contain the
  > higher layers of the architecture
- `rfc-1122` §1.1.1
  > The networks are interconnected
  > using packet-switching computers called "gateways" or "IP
  > routers" by the Internet community
- `microsoft-osi` §Network layer
  > This layer determines the physical path that the data should take
- Note: X.200 defines relaying and places it at the Network Layer or below. Its Figure 12 draws the relay system with layers 1 to 3 only. RFC 1122 independently says routers join networks.
- Note: "Need only" is about relaying data. Real routers usually also run routing protocols and a management interface above layer 3, which the claim does not mention. Forwarding itself needs only the lower three layers, so a beginner is not misled.

### entry "osi-model": statement "osi-model-1" — ✅

The OSI model (Open Systems Interconnection model), or OSI Reference Model, describes networking as seven layers with their own functions.

- `itu-x200` §1.2
  > The term Open Systems Interconnection (OSI) qualifies standards for the exchange of information among
  > systems
- `itu-x200` §6.1.2
  > The Reference Model contains seven layers:
- `microsoft-osi` §Introduction
  > The ISO Open Systems Interconnection (OSI) Reference model describes networking as
- `microsoft-osi` §Introduction
  > a series of protocol layers with a specific set of functions allocated to each layer.
- `paloalto-layer-7` §What Is Layer 7?
  > the Open Systems Interconnection (OSI) model, a conceptual framework that standardizes the functions of a communication system into seven distinct categories.
- Note: X.200 is the defining standard for the OSI Reference Model and gives its full name and seven layers. Microsoft gives the name "OSI Reference model", and Palo Alto gives "Open Systems Interconnection (OSI) model".

### entry "osi-model": statement "osi-model-2" — ✅

Its layers, from 1 at the bottom to 7 at the top: Physical, Data Link, Network, Transport, Session, Presentation, Application.

- `itu-x200` §6.1.2
  > a) the Application Layer (layer 7);
  > b) the Presentation Layer (layer 6);
  > c) the Session Layer (layer 5);
  > d) the Transport Layer (layer 4);
  > e) the Network Layer (layer 3);
  > f) the Data Link Layer (layer 2); and
  > g) the Physical Layer (layer 1).
- Note: X.200 is the defining standard for the seven layers, their names and numbers. Its §6.1.4 makes the Application Layer the highest.

### entry "osi-model": statement "osi-model-3" — ✅

It is a framework for developing standards, not a specification to build from; internet protocols use a four-layer model.

- `itu-x200` §1.1
  > The purpose of this Reference Model of Open Systems Interconnection is to provide a common basis for the
  > coordination of standards development for the purpose of systems interconnection
- `itu-x200` §1.4
  > It is not the intent of this Reference
  > Model either to serve as an implementation specification
- `itu-x200` §1.4
  > Rather, this Reference Model provides a conceptual and functional framework which
  > allows international teams of experts to work productively and independently on the development of standards
- `rfc-1122` §1.1.3
  > The protocol layers used in the Internet architecture are as
  > follows [INTRO:4]:
- `rfc-1122` §1.1.3
  > o Transport Layer
- `rfc-1122` §1.1.3
  > o Internet Layer
- `rfc-1122` §1.1.3
  > o Link Layer
- Note: X.200 defines what the reference model is for. RFC 1122 is an Internet Standard that defines the layers of the Internet protocol suite for hosts: Application, Transport, Internet and Link, four in all. Its Application Layer bullet is quoted under presentation-layer-3.

### entry "peer-layer": statement "peer-layer-1" — ✅

A peer layer is the same layer on another machine: X.200 calls entities in the same layer peer entities.

- `itu-x200` §5.2.1.3
  > peer-(N)-entities: Entities within the same (N)-layer.
- `itu-x200` §5.2.2.1
  > (N)-subsystems of the same rank (N) collectively form the (N)-layer of the Reference Model
- `itu-x200` §5.2.2.1
  > Entities in the same (N)-layer are
  > termed peer-(N)-entities.
- `itu-x200` §6.1.3
  > These layers are illustrated in Figure 11.
- Note: X.200 defines peer entities. Its Figure 11 draws the peer protocol between the same layer of two open systems.
- Note: X.200 also allows peers inside one system, which it puts outside OSI's scope (§5.2.2.2). The claim gives the ordinary case, another machine.

### entry "peer-layer": statement "peer-layer-2" — ✅

Peers work together by their layer’s protocol, a set of rules and formats.

- `itu-x200` §5.2.2.7
  > Cooperation between (N)-entities is governed by one or more (N)-protocols.
- `itu-x200` §5.2.1.9
  > (N)-protocol: A set of rules and formats (semantic and syntactic) which determines the communication
  > behavior of (N)-entities
- Note: X.200 defines a protocol and states that it governs how peers cooperate. A layer may have more than one protocol, which the claim leaves out.

### entry "peer-layer": statement "peer-layer-3" — ✅

Except at the bottom, peers reach each other through the layer below; the lowest layer uses the physical medium directly.

- `itu-x200` §5.2.2.4
  > In order to
  > co-operate, (N)-entities in any layer, other than those in the lowest layer, communicate by means of the set of services
- `itu-x200` §5.2.2.4
  > The entities in the lowest layer are assumed to communicate directly via the
  > physical media which connect them.
- Note: X.200 defines how peer entities communicate, through the services of the layer below.

### entry "physical-layer": statement "physical-layer-1" — ✅

The Physical Layer is layer 1, the lowest layer of the OSI model.

- `itu-x200` §6.1.2
  > g) the Physical Layer (layer 1).
- `microsoft-osi` §Physical layer
  > The physical layer is the lowest layer of the OSI model.
- Note: X.200 is the defining standard for the layers and their numbers.

### entry "physical-layer": statement "physical-layer-2" — ✅

It sends and receives bits over a physical medium for the Data Link Layer above it.

- `itu-x200` §7.7.2
  > means to activate, maintain, and
  > de-activate physical-connections for bit transmission between data-link-entities.
- `itu-x200` §7.7.2
  > Physical Layer entities are
  > interconnected by means of a physical medium.
- `microsoft-osi` §Physical layer
  > This layer manages the reception and transmission of the unstructured raw bit stream over a physical medium.
- Note: X.200 defines the Physical Layer's purpose. Microsoft states the same independently.

### entry "physical-layer": statement "physical-layer-3" — ✅

It covers the electrical, mechanical and procedural means of setting up, keeping and ending these physical connections.

- `itu-x200` §7.7.2
  > The Physical Layer provides the mechanical, electrical, functional and procedural means to activate, maintain, and
  > de-activate physical-connections
- `microsoft-osi` §Physical layer
  > It describes the electrical/optical, mechanical, and functional interfaces to the physical medium.
- Note: X.200 defines the Physical Layer's purpose. The claim leaves out X.200's "functional" means, which is a shortening and teaches nothing false.

### entry "presentation-layer": statement "presentation-layer-1" — ✅

The Presentation Layer is layer 6 of the OSI model.

- `itu-x200` §6.1.2
  > b) the Presentation Layer (layer 6);
- Note: X.200 is the defining standard for the layers and their numbers.

### entry "presentation-layer": statement "presentation-layer-2" — ✅

It gives the applications at both ends a common way to represent the data they exchange, and keeps the data’s information intact in transfer.

- `itu-x200` §7.2.2.2
  > The Presentation Layer provides for common representation of the data transferred between
- `itu-x200` §7.2.2.3
  > The Presentation Layer ensures that the information content of the Application Layer data is preserved during
  > transfer.
- `paloalto-layer-7` §Meet the Layers of the OSI Model
  > The presentation layer translates application format data into a common format and vice versa
- Note: X.200 defines the Presentation Layer's purpose. Its passage goes on to say the representation is between application-entities, which the claim calls the applications at both ends.

### entry "presentation-layer": statement "presentation-layer-3" — ✅

In the internet’s own model, the application layer does the Presentation Layer’s job too.

- `rfc-1122` §1.1.3
  > The application layer of the
  > Internet suite essentially combines the functions of the
  > top two layers -- Presentation and Application -- of the
  > OSI reference model.
- `paloalto-layer-7` §Structure and Abstraction Levels
  > Application (combining the session, presentation and application layers of the OSI model)
- Note: RFC 1122 is an Internet Standard and defines the Internet suite's layers. It is not obsoleted, and the updates listed against it do not touch §1.1.3.

### entry "session-layer": statement "session-layer-1" — ✅

The Session Layer is layer 5 of the OSI model.

- `itu-x200` §6.1.2
  > c) the Session Layer (layer 5);
- Note: X.200 is the defining standard for the layers and their numbers.

### entry "session-layer": statement "session-layer-2" — ✅

It organizes the dialogue between the two ends: it sets up a session, keeps their exchange orderly, and ends the session in an orderly way.

- `itu-x200` §7.3.2.1
  > The purpose of the Session Layer is to provide the means necessary for cooperating presentation-entities to
  > organize and to synchronize their dialogue and to manage their data exchange.
- `itu-x200` §7.3.2.1
  > the Session Layer provides
  > services to establish a session-connection between two presentation-entities, to support orderly data exchange
  > interactions, and to release the connection in an orderly manner.
- `paloalto-layer-7` §Meet the Layers of the OSI Model
  > The session layer establishes, manages and terminates connections (sessions) between applications on each end of a communication.
- Note: X.200 defines the Session Layer's purpose.

### entry "session-layer": statement "session-layer-3" — ✅

It can set synchronization points, so the two ends can reset the session to a point they agree on.

- `itu-x200` §7.3.1.4
  > session-connection synchronization: A facility of the session-service which allows presentation-entities to
  > define and to identify synchronization points and to reset a session-connection to a predefined state and to agree on a
  > resynchronization point.
- Note: X.200 defines this Session Layer facility. The claim's "can" matches its being a facility the layer offers.

### entry "transport-layer": statement "transport-layer-1" — ✅

The Transport Layer is layer 4 of the OSI model.

  > d) the Transport Layer (layer 4);
- Note: X.200 is the defining standard for the layers and their numbers.

### entry "transport-layer": statement "transport-layer-2" — ✅

It carries data between the two end machines for the layers above, so they need not deal with how the transfer is done.

- `itu-x200` §7.4.2.1
  > The transport-service provides transparent transfer of data between session-entities and relieves them from any
  > concern with the detailed way in which reliable and cost effective transfer of data is achieved.
- `microsoft-osi` §Transport layer
  > This layer relieves the higher-layer protocols from being concerned about data transfer with their peers.
- `rfc-1122` §1.1.3
  > The transport layer provides end-to-end communication
  > services for applications.
- Note: X.200 defines the Transport Layer's purpose. Microsoft and RFC 1122 state it independently.

### entry "transport-layer": statement "transport-layer-3" — ✅

Its protocols run only between the two end machines, not in the routers between them.

- `itu-x200` §7.4.2.3
  > All protocols defined in the Transport Layer have end-to-end significance
- `itu-x200` §7.4.2.3
  > transport-protocols operate only between OSI end open systems.
- `itu-x200` §7.5.2.4
  > Any relay functions and hop-by-hop service enhancement protocols used to support the network-service
  > between the OSI end systems are operating below the Transport Layer
- `rfc-1122` §1.1.1
  > A host computer, or simply "host," is the ultimate consumer of
  > communication services.
- Note: X.200 defines the Transport Layer as end-to-end and states this "only" itself. RFC 1122 names the end machines as hosts and the machines between networks as routers.
- Note: Some boxes on the path, such as address translators and firewalls, read or rewrite transport headers without running the transport protocol, which the claim leaves out. An ordinary router does not take part in it.
