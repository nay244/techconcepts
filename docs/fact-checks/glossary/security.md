### entry "certificate": statement "certificate-1" — ✅

Text: "A certificate, or public-key certificate, is a digitally signed record that binds a public key to its owner, such as a website."

- `rfc-5280` §3.1
  > This confidence is obtained through the use of public key
  > certificates, which are data structures that bind public key values
  > to subjects.  The binding is asserted by having a trusted CA
  > digitally sign each certificate.
- Note: RFC 5280 is the current IETF profile that defines the X.509 certificate used on the Internet (its structure, signature and validity); the marker is correct. It is not obsoleted. Its updates were reviewed by title; RFC 9925 (2026) adds a placeholder signature for unsigned certificates in contexts where no one checks the signature, such as trust anchors, which is a rare case the definition may leave out.
- `nist-sp800-52r2` §2.1
  > In these guidelines, the terms “certificate” and “public-key certificate” are used interchangeably.
- `rfc-4949` §4
  > a digitally signed data structure that
  > attests to the ownership of a public key.
- `paloalto-tls-certificate` §TLS Certificate Explained
  > When a browser connects to a server, the TLS certificate acts as a digital passport. It contains the server’s public key, the domain name, and the digital signature of the issuing certificate authority (CA).
- Note: "such as a website" is an everyday example of a subject; the Palo Alto page names the server's domain as what the certificate carries. Confirmed by the defining standard and by RFC 4949 independently.
