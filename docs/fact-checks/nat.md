### units[0].steps[2].deep[0] (step "second-device", Go deeper) — ✅

Two devices sharing one outside port to the same site would be “port overloading”. The standards say a NAT must not do it, since both couldn't then connect to that site at once.

  > the same mapping are defined in [BEHAVE-UDP] to have a "Port
  > assignment" behavior of "Port overloading". Such behavior is
  > undesirable, as it prevents two internal endpoints sharing the same
  > mapping from establishing simultaneous connections to a common
  > external endpoint.
  > … A NAT MUST NOT have a "Port assignment" behavior of "Port
  > overloading" for TCP.
- Note: RFC 5382 (BCP 142) defines the TCP behavioural requirements for NATs, including this one; the marker is correct.
- `rfc-4787` §4.2.1
  > A NAT MUST NOT have a "Port assignment" behavior of "Port
  > overloading".
  > … This requirement must be met in order to enable two
  > applications on the internal side of the NAT both to use the same
  > port to try to communicate with the same destination.
- Note: RFC 4787 (BCP 127) defines the port-assignment behaviours, port overloading among them; the marker is correct.
- Note: both RFCs are updated by RFC 7857. ### units[0].learn.facts[8] ("fact-timeout") — ✅

How long a row lasts: while its connection is in use, and for a while after it goes quiet; the standards ask for at least 2 minutes for UDP, except to some well-known ports, and at least 2 hours 4 minutes for an open TCP connection; routers differ.

  > minutes, unless REQ-5a applies.
  > … For specific destination ports in the well-known port range
  > (ports 0-1023), a NAT MAY have shorter UDP mapping timers that
  > are specific to the IANA-registered application running over
  > that specific destination port.
- Note: RFC 4787 defines the UDP mapping timer; the marker is correct.
- `rfc-5382` §5
  > In such cases, the value of the "established
  > connection idle-timeout" MUST NOT be less than 2 hours 4 minutes.
- Note: RFC 5382 defines the TCP idle-timeouts; the marker is correct. The requirement applies when the NAT cannot tell whether the endpoints are still active, which is the ordinary case for a home router. RFC 7857 does not change the 2 hours 4 minutes.
- `rfc-2663` §2.6

  > deal both from application to application and for different sessions
  > of the same application.
